# 已知问题

## CornerScape 页面批量生成提示词只成功一条

- **现象：**在 CornerScape 页面执行“批量生成提示词”时，批次中只能成功一条。
- **预期：**批量请求中的各条提示词都应按各自结果完成处理。
- **复现信息：**尚未记录项目、模型、批次数量及错误日志。
- **状态：**代码已修复：批次等待全部条目完成，单次文本供应商调用受共享并发闸门控制；失败条目会结束为“生成失败”。针对批次等待、供应商闸门和不支持类型新增回归测试。真实模型端到端结果待复测。

## CornerScape 页面生成图片后任务栏没有任务记录

- **现象：**在 CornerScape 页面生成图片时，任务栏中没有对应的任务记录。
- **复现信息：**尚未记录项目、模型及生成方式。
- **截图日志：**`POST /api/cornerScape/getAllAssets` 返回 200；随后多次 `POST /api/assets/pollingImageAssets` 返回 200（响应 41 bytes），显示客户端持续轮询图片生成状态。
- **定位：**检查到当前 Miwo API 进程没有对应 worker 进程。批量图片路由只创建 `o_job` 并返回；`o_tasks` 和上游调用均由 worker 执行，因此 worker 未运行时不会创建任务栏记录，也不会向 Sunburst 发请求。浏览器持续轮询不能证明上游请求已发出。
- **修复：**`pnpm.cmd --filter @miwo/api run dev` 现在同时启动带热重载的 API 与 worker；`dev:api` 和 `dev:worker` 仍可单独热重载启动。图片任务仍由队列 worker 按原设计执行。
- **运行限制：**本次未重启正在运行的 Miwo API；新启动配置需在下次开发启动后生效。Sunburst 上游请求尚未通过服务端或中转站日志实测。
- **状态：**代码已修复；待用户重启开发环境后进行图片任务及 Sunburst 端到端复测。
