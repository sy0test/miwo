# Miwo 设置与计费流程改造

**状态：** 已批准，待实施计划审阅  
**已确认方向：** 测试阶段由管理员手动充值；工作台侧栏常驻显示可用余额；为现有用户和新用户创建零余额账户。

## 目标

让登录后的用户能够直接查看可用余额和账户活动；管理员能够通过清晰的流程管理模型授权、价格和充值；同时清理过时或不应向普通用户开放的设置项。本次新增或调整的页面功能、导航、按钮、状态提示和错误提示均以简体中文呈现。现有技术标识、API 路径和代码标识保持原样。

## 当前问题

- 工作台左侧工具栏仍有反馈和 GitHub 快捷入口，且工作台每两分钟轮询一次更新信息。
- 设置弹窗没有按角色过滤，多项系统设置会暴露给普通用户。当前 MySQL 部署不再需要数据库操作页面。
- `loginConfig` 页面修改的是当前用户自己的用户名和密码，适合普通用户保留。
- 计费页面把个人账户信息和管理员表单混在一起，标签偏测试界面；管理员充值还需要先建待处理订单，再输入外部交易号确认。
- 模型授权和计费账户是两套独立机制。有效授权不会创建余额账户。现有用户可能没有 `o_account` 行，导致生成任务在冻结费用前失败。

## 角色与导航

### 普通用户

设置弹窗只显示以下项目，并按此顺序排列：

1. 界面设置
2. 计费账户
3. 语言设置
4. 登录配置
5. 退出登录

普通用户隐藏其余所有设置项。「计费账户」进入现有 `/billing` 路由。工作台左侧工具栏底部常驻显示余额；点击余额也进入计费账户页。

### 管理员

管理员保留仍有用途的现有高级设置，但当前 MySQL 产品不再提供数据库操作和更新检查。管理员仍可使用计费管理中的手动充值、模型授权和生效日期价格配置。计费管理与管理员自己的账户信息应有清楚的分区。

按角色显示界面只是易用性边界。必须保留现有服务端授权校验，不得弱化。

## 工作台工具栏与更新功能

- 移除左侧工具栏中的「反馈问题」和 GitHub 快捷入口。
- 保留设置入口。
- 移除自动版本轮询、更新提示/徽标以及手动检查更新和更新操作。
- 管理员可保留不含更新操作的「关于」信息，除非产品审阅另作决定。
- 从当前 MySQL 产品中移除数据库设置菜单入口、组件入口及对应前端操作页面。
- 仅因前端移除数据库设置，不删除无关数据库 API 路由或数据表。

## 余额展示与账户生命周期

- 工作台左侧工具栏底部常驻显示当前登录用户的可用余额。可用余额为 `balanceMicro - frozenMicro`，并以整数微人民币值格式化为人民币金额。
- 点击余额进入计费账户页。冻结金额、交易流水、用量和充值记录在计费账户页完整展示。
- 余额从当前登录用户的账户 API 加载。加载期间显示稳定的加载状态；请求失败时不得伪装成零余额，应显示中文错误状态并提供进入计费账户页或刷新的入口。
- 管理员充值成功或发生其他相关账户操作后，应刷新余额展示。返回工作台或计费账户页时重新获取服务端权威数据。
- 为所有缺少账户的现有 `o_user` 补建零余额 `o_account`；新用户创建时也在同一业务流程中创建账户。零余额不是赠送余额；实际产生计量费用的任务在充值前仍不能提交。
- 账户创建必须遵循现有账本的整数金额、版本、冻结余额和幂等性约束。不得绕过账本直接改写余额。

## 计费页面信息架构

### 普通用户账户页

首先展示当前用户账户，并以可用余额为主要信息；冻结金额作为次要信息展示。账户活动按清晰的中文名称分组展示：

- 充值/入账记录及订单状态
- 按服务商和模型统计的用量
- 包含金额和变更后余额的账本流水

页面文案应简洁并使用中文。加载中、无记录和请求失败等状态应明确区分；不能把账户不可用或请求失败显示成“暂无记录”。

### 管理员视图

管理员自己的账户信息与管理操作分开展示。管理员区域提供彼此独立的流程：

- 管理员手动充值
- 模型访问授权
- 模型生效价格配置

普通用户看不到这些管理操作。避免把多个无关表单连续堆放在同一页面区域。本次改动范围内的导航、表单标签、按钮、表格列、状态、校验和错误提示均使用简体中文。

## 测试阶段手动充值

- 本阶段不提供用户自助付款或外部支付渠道。
- 管理员填写目标用户、人民币金额和必填的操作原因，并明确确认充值。
- 确认成功后，在同一事务内创建已完成的手动充值记录、增加用户可用余额并追加对应账本流水。成功后按现有“尽力写入”的审计策略记录管理员审计事件。
- 如果目标用户缺少账户，在同一事务中安全地初始化零余额账户，避免充值单已创建但因账户缺失无法入账。
- 操作必须有管理员权限校验；校验目标用户存在、金额为有效正数；提供并复用稳定的幂等键，确保重试同一请求不会重复充值。
- 用户刷新后能看到更新后的余额和充值记录。模型授权继续作为独立管理操作；只创建授权不会增加余额。
- 新流程不要求填写外部交易号，也不创建新的待支付订单。已有 API 兼容性和历史待处理记录必须妥善处理，不得静默篡改或丢弃历史记录。

## 不在本次范围内

- 在线支付渠道、支付回调、用户发起退款、用户提交付款凭证。
- 改动模型授权匹配规则、模型任务派发、服务商配置或价格计算语义。
- 仅因为前端数据库设置页移除而删除服务端数据库 API。
- 除非另行提出，不改变管理员对无关高级设置的访问权限。

## 验收标准

1. 左侧工具栏不再显示反馈或 GitHub 快捷入口；更新轮询、徽标、检查和更新流程均已移除。
2. 普通用户只看到规定的五项设置；管理员保留仍适用的高级设置，但不再看到数据库和更新功能。
3. 所有工作台路由的侧栏都能显示当前登录用户的可用人民币余额，点击后进入计费账户页。
4. 缺少账户的现有用户以零余额初始化，且有效的既有账户和余额不被改变；新建用户自动获得账户。
5. 缺少账户不再导致模型任务提交时报 `Account not found`；零余额时应明确提示余额不足，并在充值前阻止计量任务。
6. 管理员可通过一次确认完成手动充值，并看到已完成订单、对应流水、审计事件和更新后的余额；重复提交不能重复入账。
7. 普通用户看不到也不能调用手动充值、模型授权或价格配置；服务端仍强制执行管理员权限。
8. 模型授权、价格配置和个人账户活动有清楚区分；界面不暗示已接入真实支付渠道。
9. 自动化测试覆盖角色可见性、账户初始化/回填、充值事务与幂等性、权限校验、余额加载/错误状态，以及无记录和余额不足的用户流程。
10. 本次新增或调整的页面功能、导航、表单、操作反馈和错误状态均使用简体中文呈现；不得以英文作为默认界面文案。

## 已确认的假设

- 当前部署只使用 MySQL；数据库操作设置页对所有角色移除。
- 管理员对非数据库、非更新类高级设置的现有访问权限保持不变。
- 侧栏显示可用余额而非总余额；计费账户页同时显示冻结金额。
- 手动充值是测试阶段由管理员执行的账户入账流程，不代表在线支付功能。
- 代码标识、API 路径、数据库表名和协议字段等技术标识可继续使用英文；面向用户的页面文案和本次项目文档使用简体中文。
