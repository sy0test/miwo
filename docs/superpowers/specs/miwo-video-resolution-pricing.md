# Miwo 视频分辨率定价

**状态：** 设计已批准，待实施计划审阅
**已确认的兼容策略：** 启用分辨率专属价后，480p/720p 必须精确匹配，不回退到旧统一价。

## 目标

为视频模型提供按输出分辨率计价的每秒费率，当前覆盖 480p 和 720p。提交预估与实际 Provider 用量必须使用同一分辨率和同一生效价格规则；保留尚未启用分辨率价的旧模型配置。

## 当前问题

- 管理员价格表单只有通用 `video_second` 单位。
- 单条与批量视频任务的提交预估只按时长选择该通用单位。
- 实际 Provider 用量只记录视频秒数，未将任务分辨率纳入价格选择。
- 视频任务本身已经携带 `resolution`，不需要从模型或供应商猜测。

## 价格单位与历史

- 在现有 `o_price.unit` 字符串字段中增加 `video_second_480p` 和 `video_second_720p`，不新增数据库列或迁移。
- 模型价格配置界面可分别追加“每秒视频（480p）”和“每秒视频（720p）”价格；历史表以对应中文名称显示。
- 保留 `video_second` 作为旧版通用价格，不自动改写、复制或删除历史记录。
- 价格仍按服务商、模型、计价单位和生效时间追加；金额精度、生效时间排序、重复价格约束均保持不变。

## 选择价格规则

对分辨率为 480p 或 720p 的视频请求，在其价格计算时刻执行：

1. 若该模型在该时刻尚无任何已生效的分辨率专属价，使用旧 `video_second` 价格，保持现有配置可用。
2. 若该模型在该时刻至少有一档已生效的分辨率专属价，必须取得请求分辨率对应的专属价；缺少当前分辨率的有效价格时拒绝预估或计费，不回退至通用价。
3. 其他分辨率继续使用 `video_second` 通用价格，本次不增加其他分辨率档位。

价格选择应共享实现，避免提交预估和实际计费采用不同回退逻辑。历史价格解析仍基于调用/任务对应时间，未来生效记录不能提前启用分辨率定价模式。

## 预估与实际用量

- 单条与批量视频提交预估均把请求中的 `resolution` 传给价格选择逻辑；冻结金额按总秒数乘以对应档位价格计算。
- 视频 Provider 调用的预留/准入和实际用量记录均携带任务分辨率；使用同一价格选择规则和精确的生效时间。
- 用量记录保留已选择的 480p/720p 维度，`priceId` 仍指向实际采用的价格行，包括未启用分辨率价时回退到的通用价格行。
- 时长、微元精度、账本舍入、幂等、每日授权限制和任务队列语义保持不变。

## 安全与兼容

- 价格写入仍仅允许管理员；管理员 API 仅接受既定单位值，不接受任意单位字符串。
- 不改现有数据库价格数据，不做迁移，不重启生产 API。
- 原有模型未配置任何生效分辨率价时继续使用 `video_second`；分辨率价格逐档生效后，缺少的档位应显式失败，防止继续按统一价错误收费。
- 不改变图像、文本、Token、字符计价和其他业务流程。

## 验收标准

1. 管理员可以分别查看和追加 480p、720p 每秒价格，历史价格表正确标记档位。
2. 管理 API 接受两种新单位并拒绝不允许的单位；旧单位仍有效。
3. 无生效分辨率价的模型，480p/720p 预估和实际用量继续按旧通用价处理。
4. 任一分辨率档位已生效后，请求必须命中自身档位；缺档时预估/计费失败，不使用通用价格。
5. 单条及批量提交按请求分辨率计算预冻结金额；实际 Provider 用量按相同规则计价并记录对应维度与价格 ID。
6. 同一计费时刻、分辨率、模型和秒数下，预估与实际价格一致；未来价格不会提前启用。
7. 回归测试覆盖两档价格、部分缺档、旧价回退、其他分辨率、历史生效时间、单条/批量预估及实际计费幂等。
8. 不需要数据库迁移，现有非视频价格与视频通用价格历史保持不变。

## 不在范围内

- 自动从供应商读取市场价或费率。
- 自动推导或迁移现有统一视频单价为 480p/720p 单价。
- 增加 1080p 或其他分辨率专属档位。
- 改变任务模型参数、授权规则、余额账本或 API 认证边界。
