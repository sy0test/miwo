# Miwo 计费管理分组与模型定价信息架构

**状态：** 设计已批准，待实施
**关联规格：** `docs/superpowers/specs/miwo-settings-billing-redesign.md`

## 目标

将管理员计费操作放回对应的业务对象页面：用户授权与充值放在用户管理，模型价格放在模型配置；以用户组和模型组管理模型授权；所有余额只显示人民币两位小数，不改变微元账本精度。

## 当前实现边界

- `/billing` 同时包含个人账户与管理员充值、逐用户模型授权、价格表单。
- 管理员充值表单直接填写数字用户 ID；当前没有用户列表页或管理员用户列表 API。
- 模型授权记录位于 `o_modelGrant`，按用户绑定 Agent 或服务商/模型，并保存每日调用限额。
- 服务商模型维护在 `vendorConfig.vue`，模型标识来自 `o_vendorConfig.models`。
- 价格记录位于平台级 `o_price`，以服务商、模型、计量单位和生效时间追加。
- 余额为整数微元，当前格式化函数显示六位小数。

## 信息架构

### 用户管理

- 新增仅管理员可见的 `/admin/users` 工作区路由与侧栏入口。
- 用户列表支持按用户名或 ID 搜索；展示 ID、用户名、角色、状态、可用余额、用户组和打开详情操作。
- 角色与状态本次只读，不增加角色修改、停用或删除操作。
- 用户详情提供多用户组绑定和单步充值；充值仍要求正数金额、非空原因、确认对话框和幂等键。选中用户后不再要求输入 ID。
- 用户列表 API 仅返回管理界面所需字段，不返回密码哈希、会话令牌或其他凭据。
- 用户个人 `/billing` 只展示本人余额、订单、用量和账本活动；不再包含管理员表单。

### 用户组与模型组

- 管理员创建模型组；每个模型组包含一个或多个已配置的 `vendorId + model` 项。每项可配置启用状态与每日调用限额。
- 管理员创建用户组，并将一个或多个模型组关联到用户组。
- 每个用户可以属于零个或多个用户组；获得的模型集合是其所有已启用用户组关联的模型组并集。
- 当同一用户通过多个模型组获得同一个模型时，适用所有有效限额中最严格的非空值；全部为空时不限制每日调用数。每日计数仍按用户、服务商、模型独立计算。
- 模型授权解析必须在服务端执行；隐藏/显示 UI 不构成授权。计量预留时必须以用户组授权结果判定可用模型。
- 现有 `agentKey` 授权继续走独立的 `o_modelGrant` 路径，不自动转为模型组成员，也不改变其准入语义。
- 追加迁移将现存的每用户 `vendorId + model` 授权复制为该用户专属的历史用户组与模型组，逐项保留 enabled 和 dailyLimit，然后建立用户组、模型组关联及用户成员关系。迁移只复制/初始化缺失关系，不删除或改写已有授权行；新运行时代码不再把历史逐模型授权当作模型组以外的授权来源。

### 模型价格

- 价格配置入口放在现有服务商模型配置中对应模型的详情区域，不再放在 `/billing`。
- 每个模型详情展示当前及历史价格，管理员可按计量单位追加单价与生效时间。
- 后端继续追加式写入 `o_price`；不编辑/删除历史价格，不改变价格生效选择与计费计算语义。
- 服务商或模型标识由所选模型确定，避免管理员手动输入容易出错的 ID。

### 金额展示

- 数据库存储、API 权威值、账本、冻结/结算和幂等逻辑继续使用整数微元。
- 工作台余额、个人计费账户、用户管理列表和用户详情中的可用/冻结/总余额均使用精确整数运算格式化为人民币两位小数，按最接近分四舍五入。
- 价格、充值输入、账本金额的输入和计算精度不因余额展示规则改变；微元精度转换必须继续避免浮点累积误差。

## 数据与 API 边界

- 新增迁移采用追加编号并注册到内存迁移清单，不修改既有迁移。
- 新表策略必须同步更新 `apps/api/src/db/policies.ts` 与数据库策略测试。
- 用户组/模型组 CRUD、用户列表、用户组成员维护和模型组映射路由均执行 `requireAdmin`；目标用户写入仍遵守目标租户上下文。
- 组管理接口提供列表/详情所需的数据。输入必须校验组名、重复成员、服务商/模型、每日限额及 ID 范围；删除/编辑组时不产生越权或静默权限丢失。
- 价格写入 API 仍为管理员专用。前端复用当前计费价格 API，不复制新的计价逻辑。
- 注册、登录、余额、充值事务、审计和账本语义保持原规格。
- `apps/api/src/router.ts` 是生成文件，必须通过既有路由生成脚本更新。

## 简体中文界面

新用户管理页、分组对话框、模型价格面板、表格列、按钮、校验错误、加载/空/失败状态全部使用简体中文。不要新增用户可见的英文回退文案。

## 不在范围内

- 在线支付、退款、角色/状态管理、用户删除。
- 管理员查看所有用户的详细用量或所有账本流水（本次充值确认与账户概览需要的内容除外）。
- Agent 授权分组化。
- 更改计费价格计算、账本精度或每日调用计数口径。
- 清理或删除旧的 `o_modelGrant` 记录。

## 验收标准

1. 普通用户不能看到或调用用户管理、组管理、全局模型价格管理及管理员充值接口。
2. 管理员可以搜索用户、查看安全裁剪后的账户摘要、为用户绑定/解绑一个或多个用户组，并从用户详情完成带原因和二次确认的充值。
3. 管理员可以维护模型组成员、用户组映射，用户的模型授权按组关系生效；未被任何组授权的用户不能通过模型计量准入。
4. 既有逐模型授权及每日限额迁移前后等价；重复运行迁移不会重复创建关系；既有 Agent 授权语义不变。
5. 多组重复授权同一模型时按最严格的非空每日限额执行；无授权时拒绝准入。
6. 模型详情能查看价格历史并追加生效价格；`/billing` 不再包含价格/授权/管理员充值表单。
7. 工作台、个人账户和用户管理各处余额均显示两位小数，舍入由整数运算完成，账本/API 微元值保持不变。
8. 新增 API、迁移、授权解析、用户管理、价格面板和格式化逻辑均有针对性回归测试；API/Web 类型检查及生产构建在环境允许时验证。
